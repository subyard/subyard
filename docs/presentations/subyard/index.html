Requirement / Choose an isolation boundary

Container or VM?

Shared OS processes, or a separate guest operating system.

Container

Low overhead
Container processes
Other processes
Host OS · one shared kernel
Host hardware

Ordinary processes. Isolated views.

Namespaces separate what programs can see.
Programs run on the same OS kernel as the host.
CPU / RAM limits can overlap — overcommit.

Virtual machine

Stronger isolation
Guest OS + kernel
Guest OS + kernel
Hypervisor · hardware virtualization
Host hardware

Reserved RAM and disks can sit idle.

Virtualization adds runtime CPU overhead.
Available on proprietary hosts: Windows / macOS.
Can also run proprietary guest OSs.

Choose the isolation boundary and resource policy separately.
VMs can overcommit too; actual memory, disk, and CPU costs depend on the setup and workload.

Requirement / Account for every allocation

Every allocation has an owner.

Use a broker to track leases, enforce capacity, and reclaim abandoned resources.

Lease record

Who · What · Until

Owner and purpose
Allocated slot
Expiry and heartbeat
Cleanup state

A slot is reusable only after
cleanup has been confirmed.

01 / Admission

Pool full → refuse

No unbounded allocation
when capacity is exhausted.

02 / Active lease

Heartbeat → retain

The resource has a current owner
and a bounded lifetime.

03 / Release or expiry

Fence → reclaim

The reaper fences access,
stops guests, and deletes disks.

04 / Cleanup failure

Quarantine the slot

Keep it unavailable until
safe cleanup is established.

Expiry invalidates the lease. Physical cleanup follows on a reaper pass; failed cleanup blocks reuse.
